# 5. Patterns chosen by our own criteria

**Decision:** The Patterns phase is selected and grouped by one rule: a pattern is a problem that comes up again and again and can only be solved by combining building blocks from phases 2 to 6. The patterns are grouped by where the pressure comes from: load, data, correctness and reaching users.

**Why:** The earlier list came from the roadmap we started with and closely followed one site's set of seven patterns. Some overlap is natural, since a few of these problems are central to the field, but the choice and the structure should be ours.

**Costs:** Fourteen patterns instead of nine. A few titles still match common phrases (Scaling Reads, Scaling Writes), because those are the plainest names for those problems.

**Alternatives:** Keep the earlier set (simpler, but not our own selection), or drop the phase and leave patterns inside the building block phases (they combine several phases, so no single phase is the right home).
